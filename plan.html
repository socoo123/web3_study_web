链上开发手册 · 课程计划

给有 Java 工程经验、第一次做链上开发的人。 整门课从一个委托出发：客户给你一笔交易的哈希，请你判断「能不能把这个订单标成已付款？」先在比特币上弄清钱从哪里来，再在以太坊上弄清代码如何改变余额，最后把答案交成别人能复跑、能维护的服务。

怎样判断已经出师

不是背完协议，也不是独立为真实资金合约签安全意见。目标是能独立交付有明确边界的链上集成项目。一个没读过本书的同事应该能按你的交接说明完成以下验收：

客户的问题 你要交的东西 怎样才算过
这笔订单真的收到了吗？ 只读查款 API、交易证据单、对账差异表 从干净数据库重放同一区间两次，业务金额一致；错链、错资产、失败回执不入账
我能让用户自己签、自己付吗？ 钱包接入页、意图预览、确认与失败状态 客户自行拒签、切网、重开网页，页面都不误报成功；你拿不到客户私钥
这个规则真的在链上执行吗？ 小型合约、可复现部署、角色与状态测试 从源码部署出新实例，正常路径到账，未授权调用及重复结算均被拒绝；用事件和余额证明两种结果
周末黑客松能展示什么？ 一个垂直切片、开源许可清单、3 分钟演示、复现说明 评委能更换输入跑出不同结果；能指出哪一步必须上链、何处仍然信任中心服务、RPC 中断时会怎样

不要把「我可以维护索引器」误当成「我可以代管客户资产」。托管、资产发行、支付清结算、面向公众运营涉及额外风险与当地法律；课程结业不构成这些业务的资质或审计背书。

学习路线与时间预算

建议从主线开始，不同时学三种语言。 Java 负责 RPC、事件归档和服务；Solidity 只解决链上必须强制执行的规则。M06 直接用浏览器 JavaScript 请求 EIP-1193 钱包，不需前端构建；接入 TypeScript 项目时，钱包方法和事件不变。想参加 Solana 赛道再学 Rust。HTTP、SQL、事务和 JUnit 不从头教。

主线约 200 小时：每周 8 小时约 25 周，每周 12 小时约 17 周；全修约 290 小时。这是排期假设，不是能力承诺。以每周 8 小时为例：第 1–5 周完成钱包和 BTC 对账；第 6–12 周完成 EVM 和合约；第 13–20 周完成索引与钱包接入；第 21–25 周专做交付。每周把至少一半时间留给自己敲命令、解释差额、重跑失败路径。验收没过就留在本卷，不靠打卡推进。

两条出口。 想兼职：优先 M05，先接只读数据、报表和测试网集成，M10 用实际验收单报价。想参赛：完成主线基础后选 M07 或 M08，不要把跨链、ZK、AI 和 DeFi 硬塞进同一个作品；用 M10 的演示标准倒推功能。

M01 · 账本、钱包与密码学

客服说：「账页里有这笔，审批人也签了，为什么还不能标成已付？」从一张应收 2 张券的订单开始，顺着四课看：账页究竟记了谁付给谁，签名究竟签了哪几个字节，钱包派生出来的是收款地址还是找零地址，最后，你的程序连的是哪条链。

课次（进入正文） 要讲透的问题 动手与过关标准
01 两本账如何对齐 状态与历史；块头、父哈希、Merkle 承诺；节点验证与共识分工。哈希链接能暴露改动，不能独自决定哪条链有效 手工重算一个四叶树的根。解释一份包含证明为什么不能证明交易业务合法，也不能证明该块是当前主链
02 哈希、签名与加密 摘要不保密；签名绑定精确字节；认证加密保护机密性与完整性。区分 secp256k1、Ed25519 和 AES 的用途 用 Java 改一位金额，原签名失效；改密文，认证解密失败。能指出公钥能做什么、不能做什么
03 钱包到底保存什么 私钥、公钥、地址、助记词、可选口令、HD 派生路径；观察钱包与签名器的权限差别；BTC 描述符与 EVM 地址不是同一种备份 用公开的 BIP 测试向量离线核对派生结果，更改路径比较地址。不把公开样本当私人钱包；给出仅凭地址无法恢复签名能力的原因
04 运行自己的第一条链 节点、钱包、浏览器、RPC 分别是谁；regtest、Anvil、公共测试网和主网不能混用；记录版本与网络身份 分别读到 Bitcoin 的 chain=regtest 与 EVM 的 eth_chainId=0x7a69。提交一份不含密钥的环境记录，故意选错链时客户端在发交易前停止

完成四课后做卷末验收：接手一张异常付款工单。不看范例输出，由另一位同事换输入，检查你是否会把“已签”“已包含”或“已连上节点”误报为“已付款”。

M02 · 比特币：从 UTXO 到收款凭证

Java 里的「扣余额」不是 Bitcoin 的数据模型。输入引用上笔交易的输出，花费时整枚消耗；剩下的钱通常回到新找零输出，而不是在旧输出上改数字。

课次（进入正文） 要讲透的问题 动手与过关标准
05 链、工作量与确认 工作量证明、累计工作、区块补贴与手续费；coinbase 成熟期；节点验证规则与矿工选择交易的区别 在 regtest 自行出块。比较可花与未成熟金额；把「进内存池」「进一个块」「达到业务阈值」分成不同状态
06 亲手核对一笔付款 txid:vout、输入见证、收款、找零、费率 sat/vB；手续费不作为显式输出存在 做双钱包实验。沿每个输入找到前序金额，用整数 sat 核对输入总额减去所有输出等于手续费，且付款方确认数与收款方流水一致
07 地址与花费条件 Script 锁定条件、见证与 SegWit；区分 P2WPKH 与 Taproot 的输出类型、地址编码和签名方案。txid 与 wtxid 各描述什么 解码两种本地地址的 scriptPubKey。从输出类型判断未来需要哪类解锁数据，而不是从地址猜持有人；解释 weight 与 vsize 的关系
08 PSBT 与钱包分工 BIP-174 的构造、补全、签名、合并、最终化和广播；描述符只读收款、变更地址与费用预览 在两端角色分离的 regtest 流程里传递 PSBT。签名前列出收款/找零/费率；只读端不能独立完成签名；提交最终交易与原支付意图的比对单

完成四课后做卷末验收：复核一笔新的付款工单。阶段口试：同事看到一笔交易有两个输出，就断言金额较大的一项是找零。请说明缺少什么证据；比较钱包自身地址归属信息与纯链上启发式的可信度。

M03 · 以太坊：账户、Gas 与回执

把同一张付款单换到账户模型。此时不用选 UTXO，却多了链 ID、账户 nonce 和执行失败仍付费的问题。先过 M01 的网络核验；建议做过 M02 的双钱包对账。四课只用自己的临时 Anvil，不需要持有 ETH。

课次（进入正文） 要讲透的问题 动手与过关标准
09 账户与执行 余额、nonce、code、storage；交易与消息调用；确定性状态转换；执行客户端与共识客户端分工，PoS 的确认与最终化 对照同一个区块高度读取两个账户；解释 latest、safe、finalized 的适用场景和本地节点与公开网络的差异
10 签名与序号 Type 2 交易字段、链 ID、发送者恢复、pending/latest nonce；相同业务请求和相同签名原始交易不是一回事 两个本地请求争用同一发送账户，设计串行分配与持久化策略；RPC 超时后不靠生成新 nonce 来猜前一笔是否成功
11 Gas 与收支平衡 wei、gwei、ETH；上下限、base fee、priority fee、实际单价；执行费不等于 gasLimit × maxFeePerGas 跑 Java 回执实验。固定区块端点后对账：接收方增加支付额，发送方减少支付额及实付费用。说明公式在 L2 不一定完整
12 从提交到最终化 哈希不是收据；状态从未知、待打包、已入块到确认；status=0、回执暂缺与链重组；浏览器是证据入口而非裁判 对照 eth_getTransactionReceipt、区块哈希和高度；为成功、回滚、RPC 不可用各给出用户能理解的状态，不把 null 翻译成「失败」

完成四课后做卷末验收：复核一笔 ETH 付款工单。把账户差额、实际费用、回执所在块与订单门槛放在同一份交接记录里。

M04 · Solidity：写得出，更要证明做对了

贯穿案例是里程碑托管：付款者锁入本地测试资产，符合约定时结算，超时按约定退款。先写清谁有权操作、钱在哪里，再写代码。此案例不是可直接承载客户资金的产品。

课次（进入正文） 要讲透的问题 动手与过关标准
13 从 JVM 切到 EVM ABI、selector、calldata、memory、storage；映射没有天然遍历；整数精度和显式转换；外部调用不同于 Java 方法调用 用 Solidity 写金额登记，分别经 Cast 与 Java 编解码同一次调用；给出输入字节、读取结果与单位
14 托管状态机 payable、调用者、角色、截止时间、关键事件；链上不能自行到点执行，需外部交易触发 写「待付款→已锁定→已结算或已退款」转移表。锁款为零、错误角色、过期边界和第二次结算都有确定结果
15 Foundry 测试与安全边界 Forge 单测、模糊输入、跨操作不变量；最小权限、检查与状态更新先于外部交互、拉取式付款；库依赖的版本边界 对自己合约测试：累计支出不超过入金、单笔款不重复领取；保存失败输入并修复测试针对的逻辑，不把覆盖率当安全证明
16 发布与可维护性 构建配置、固定编译器与库、部署交易、源码验证、ABI 与地址清单；不可升级与代理升级各让谁承担迁移风险 从空链重部署并让同事只凭清单完成调用；清单含 chainId、块号、部署哈希与构建参数。写出停用旧入口的办法，不声称能回滚确认交易

完成四课后做卷末验收：接手一份托管部署清单。换一条空链后，先找出旧凭证为什么失效，再让同事只凭新清单核对实例。

M05 · Java：把链上事实变成业务流水

先修是 M03 的回执与确认和 M04 的托管部署清单。给 Java 服务的不是「已付款」消息，而是一份仍需核对的证据：同一交易可能等不到回执，落库的事件也可能随旧区块退出规范链。四课用同一个本地托管合约，把节点观察、可撤销的索引和商户账本分开。

课次（进入正文） 要讲透的问题 动手与过关标准
17 RPC 适配层 Java HttpClient 看原始 JSON-RPC，再用 web3j 做类型与 ABI 封装；超时、限流、分段查询、幂等读取；BigInteger 与最小单位 写只读 /receipts/{hash}，区分无回执、执行回滚、RPC 错误；数据库和 JSON 边界都不经过浮点数
18 从日志建索引 topic、indexed 参数、ABI、eth_getLogs 范围扫描；WebSocket 只做低延迟提示；PostgreSQL 保存扫描位置和块哈希 停掉订阅仍可从游标补扫。重复喂入同一批日志后结果不变；识别事件的链、区块哈希、交易哈希、logIndex，检索时限定合约地址
19 重组与事务边界 校验父块、寻找共同祖先、旧记录失效、可逆派生状态；扫描游标与写库在同一事务提交。退款流水不能靠删除历史伪造 在自有开发链快照分叉出两段不同历史；重启索引器后旧分支不计入余额，新分支只算一次，保留修正记录
20 订单对账与运维 支付意图、整数金额、资产白名单、确认策略；链上观察、业务入账、通知 outbox 拆开；观测扫描滞后和差异 写一个 Spring Boot 查款服务。重复回调、漏块补扫、少付和错币种各跑一次；交一张差异表和从备份恢复的操作单

完成四课后做卷末验收：对账与备份恢复。验收对象是托管受益人的应领款，不是钱包已经收到的转账。

M06 · 钱包接入、代币与 DeFi

先修：M04 的合约调用与部署、M05 的订单与资产核对。用户签了登录消息，能不能替他扣款？沿着登录会话、代币额度、池子报价和价格时间戳，逐步找出每个决定需要的凭证。所有写操作限本地；签名页单独启动，课程站本身不请求连接权限。

课次（进入正文） 要讲透的问题 动手与过关标准
21 钱包与登录 EIP-1193 Provider、账户/网络切换、拒签；SIWE 的域、nonce、时效和会话；登录签名不是转账授权 浏览器端请求签名，Java 后端验证并一次性消费挑战。拒签不建会话，换账户后旧界面不能冒充新账户
22 资产接口与授权 ERC-20 的余额、allowance、decimals；ERC-721 的所有者与授权；ERC-1155 的多资产模型。签名授权与链上交易是两步 本地 6 位与 18 位资产都显示与结算正确；有限额度 approve 后分别跑额度内与超额操作；页面列出 spender、资产和上限
23 AMM 与滑点 用恒定乘积池解释储备、价格影响、费用与最小输出；区分报价、成交量与证据。再读 Uniswap 集中流动性中的价格区间，不套用同一公式 两个自建测试币构成教学池，给同样方向的两种输入量报价，比较单价；设置不可满足的最小输出，核对交易未交换资产
24 借贷与价格输入 抵押率、清算阈值、健康度、估值单位；价格源精度、最后更新时间与降级；只读展示不等于给出投资建议 对本地仓位做健康度计算，与合约读数对照；给过期价格或缺价时拒绝给出可执行报价，不把缺值当零

完成后做卷末工单 D-624：核对登录、授权、成交与估值四联凭证。继续主线请转 M10 交付计划；M07–M09 是选修，不是门槛。

M07 · L2、智能账户与跨层状态〔选修〕

先修：M03 的回执与最终性、M04 的部署清单、M06 的签名与授权。沿 Base / OP Stack 分清谁执行、谁付费、哪一层能证明到账；对照 Arbitrum 时只迁移概念，不假定相同的费用和提现时间。

课次（进入正文） 要讲透的问题 动手与过关标准
25 Rollup 信任边界 排序器、批次、数据可用性、L1 结算；optimistic 与 validity rollup 的验证区别 标出一次 L2 转账的执行、数据发布、最终化分别在哪里；说明排序器返回回执为何不等于 L1 已终结
26 L2 费用与部署 EVM 兼容不等于在费用估算、最终性和 RPC 能力上一致；分别记录执行与数据相关费用 同一份合约在本地与可选 Base Sepolia 使用独立网络清单；从回执及链专用字段解释差额，未知字段不能默认为零
27 智能账户与代付 ERC-4337 的 UserOperation、EntryPoint、bundler、paymaster；与 Safe 的多签阈值、EIP-7702 的委托机制分别作何取舍 从一次受控操作分别查用户操作哈希和外层交易哈希；限定代付对象与预算，预算耗尽不显示为免费成功
28 跨层消息跟踪 官方桥的发起、证明/验证、领取是不同阶段；源链哈希不等于目标链到账，等待期依网络而异 用公开测试网既有记录做双端只读跟踪；给「已发起、可领取、已完成」各列证据。没有目标侧证据只报处理中，不建议第三方桥

四课完成后做卷末验收：跨层状态报告与代付预算。完成这条选修不会代替 M10 的主线交付验收。

M08 · Solana：换一种状态模型〔选修〕

面向愿意投入 Rust 的读者。不是把 Solidity 语法翻译一遍，而是把「数据放在哪里、谁能写、谁必须签」重新走一遍。

课次 要讲透的问题 动手与过关标准
29 Rust 最短路径 所有权、借用、枚举、Result、序列化；和 Java 引用语义、异常的差别只讲程序需要的部分 完成一个可序列化的订单结构；输入长度错误返回显式错误，不崩溃
30 账户与交易 program 与 data account、owner、signer、writable；指令、费用支付者、recent blockhash、确认级别 在本地 validator 发送付款，列出签名者和可写账户；区分 blockhash 过期与已经确认，不凭客户端超时断言失败
31 Anchor、PDA 与 CPI 用 seeds/bump 定位数据，约束账户所属程序与授权者；跨程序调用与能力传递 写一个每人独立的登记程序，两个用户数据分开；错误的账户组合不能更改登记内容，保存日志及交易签名
32 SPL Token 与交付 mint、token account、ATA；mint authority、freeze authority 和钱包地址是不同角色 创建无价值本地 mint，向 ATA 转账；用最小单位复算两侧变化，交出部署 ID、账户结构与可复跑的客户端

课次 先修与主题 动手与过关标准

M10 · 从可运行的代码到可接手的项目

课次 要讲透的问题 动手与过关标准
37 接需求与估价 哪条链、资产与合约地址，读还是写，谁签名，何谓完成；节点配额、运维和主网职责由谁承担 给「帮我接一下钱包」写两版范围：只读对账与非托管发起。分别列交付项、排除项、依赖、验收人、里程碑、变更与质保边界

39 移交与事故演练 地址簿和权限表、交接密钥所有权而不是索取客户密钥；依赖许可、数据保留、告警、备份与恢复 接手人仅用交付包独立运行；模拟 RPC 断连，告警后补扫恢复；写明哪些链下步骤能撤回，哪些链上动作不可逆
40 48 小时黑客松 选官方命题和允许的依赖，先做垂直切片，再留出复现和讲解时间；不靠预录成功掩盖现场失败 0–6h 明确问题和评审条件；6–24h 跑通链上核心；24–36h 整合与故障处理；36–48h 冻结、录演示、提交。用 3 分钟说明问题、交易证据、限制和下一步

作品集要能被别人检查。 提交源码版本、锁定的工具版本、干净环境运行命令、部署清单、已脱敏的交易证据、正常/失败验收记录、简短演示。对账方向提交差异报表；合约方向提交角色表和不变量；参赛方向另附比赛授权、素材许可与规则核对。不用奖项或收益代替技术证据。

实验设计与安全边界

「真实」指真实密码库、节点、签名、矿块、回执和日志，不是必须花真币。以下实验都不要求真实助记词、水龙头或公共 RPC。每次实验先确认网络，再记录输入、执行命令、观察证据，最后关闭临时环境。提交作业不包含助记词、私钥、RPC 凭据、钱包文件或可识别客户的资料。

场景 环境与动作 留下的证据；容易误判的地方
消息授权与机密性（02） JDK 临时密钥签名后改动消息；用独立 AES 密钥加密并改动密文 原文验签通过、改动不通过；密文改动被拒。签名本身没有隐藏原文
BTC 商户收款（06） Bitcoin Core regtest 付款钱包给收款钱包转账，控制出块 查前序输出、手续费、找零、收款与确认数；不能把一笔找零算成第二笔收入
Java 查款（11） Anvil 上两个临时账户转 ETH，通过 RPC 取交易和回执 金额和费用逐 wei 对平；哈希、回执成功、业务可入账是三层判断
钱包恢复演练（03） 离线使用公开测试向量、明确口令和派生路径 重建预期地址。恢复出不同地址时先比路径和口令，不往网页粘贴任何真实助记词
只读索引灾后恢复（19–20） 私有链推进后回退快照并形成另一分支；中断进程、从旧游标继续 旧 hash 对应记录保留修正轨迹；按新规范链重算应领，重复回调不重复生成通知意图
DApp 登录与授权凭单 独立浏览器测试资料；在登录台拒签或切网；另起 Anvil 生成授权凭单，关闭后再打开 登录不发交易，错网不签登录消息；从凭单取原交易哈希，在同一活节点找回成功或回滚的证据
公开可查的演示〔可选〕 先本地通过；只用全新测试账户与官方应用测试网，或只读查询一笔已有交易 写清网络、哈希、块号和观察时间；水龙头不可用就保留本地实验证据，不买测试币。测试网记录不等于永久存档

私有实验节点只绑定回环，不开放解锁账户的 RPC。不得复用主网钱包、连接陌生签名站、触碰他人资金或系统；不教授攻击复现、抢跑、绕过授权或密钥获取。生产接单先确认所在地区规则、合同授权范围和责任分工；涉及真实资产的合约部署与密钥管理需要独立审查，主网写入不设为毕业要求。

每课写到什么深度

  1. 从需求开始。 写出决策问题和先修，然后用一个具体输入解释机制。Java 对照只在能迁移经验或容易误判时出现。
  2. 展示证据。 给出固定的环境前提、完整命令、变量来源、输出字段解释与不固定值。至少一个算得出的例子，随后用节点实际输出复算；示意数据必须标明。
  3. 让学生做一个改变。 修改金额、签名者、网络或区块状态中的一项，先预测结果，再运行；提供解释与定位步骤，而不只是成功截图。
  4. 交出可检查的结果。 每课末尾给独立作业、答案判据、必要的协议/工具原文；阶段项目用上表做验收。工具、网络和费用规则会变，正式章节固定实验版本，并写清命令所在发行版。

图用来回答具体问题。 资金流用账页对金额，钱包、RPC 和节点用泳道时序图看谁在等谁；状态回退、Java 与协议的差异适合前后对照。M01 还要看清「往哪一支走」：所以把 Merkle 证明和钱包路径画成树，把节点换链画成分叉。复杂过程拆开，一张图只讲一个判断。

静态站和写作顺序。 Markdown 是内容源，生成的 HTML 可直接打开；阅读不需要钱包、登录、后端或在线图床。主线按 M01–M03、M04–M06、M10 的顺序交付，每批跑对应实验，再按实际赛道选择 M07–M09。目录中的课名只在正文可读时提供链接。

本地阅读直接打开 index.html。计划和各课原稿分别在 PLAN.md 和 labs/*.md，首页模板在 tools/home.html，课序在 tools/build.py。生成器用 Python 3.10+ 和 Python-Markdown 3.10.3；在装好 Markdown==3.10.3 的环境中，从项目根目录执行 python3 tools/build.py 即可更新静态页。浏览成品不需要安装 Python。

查证入口与审阅重点

  • Bitcoin：Bitcoin 开发指南、regtest 说明、BIP 规范库。指南用来理解机制，具体参数看所用版本的 bitcoin-cli help。
  • Ethereum：账户与交易文档、网络选择、JSON-RPC 接口、ERC-4337、SIWE。公共链只作可选联调，网络状态以官方当时说明为准。
  • 合约与 Java：Solidity、Foundry、OpenZeppelin Contracts、web3j。区分协议共识规则、客户端默认策略与业务确认策略。
  • 协议与多链：Uniswap、Base 网络说明、Solana 账户、Anchor、Sui Move、Lightning 规范、The Graph、Circom。
  • 参赛选题：ETHGlobal 活动、Solana 黑客松。按当届规则确认赛道、资格、截止时间和既有代码披露要求，不预设奖项或主网部署要求。

建议你先审三个决定： 以 Java 查款与非托管应用作为首个兼职方向是否合适；毕业作品是否愿意做收款对账台；第一条选修更想做 L2 智能账户，还是 Solana 程序。选修答案不影响前六卷，建议先用第 06 课双钱包实验判断讲解深度是否够用。
